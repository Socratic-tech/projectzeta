New installations use v3 only

Personal admin codes, report-only viewer codes, emailed credentials, restricted job-site QR access, and version enforcement are all part of the default installation.

1

Make the school spreadsheet

Each school uses its own private copy. Keep spreadsheet access limited to staff who actually need spreadsheet-level administration.

Make a Copy of the Spreadsheet
2

Open the spreadsheet

The bound script initializes the required tabs and security settings automatically. Look for Vocational Tracker → Setup & Credentials in the Google Sheets menu. The order of the sheet tabs may vary; their order does not matter.

3

Create the first personal administrator

Enter the administrator's name and school email in the sidebar. Their personal code is emailed and works for both Admin and Reports.

You can also set the feature-request/support email in this sidebar. After the first successful public Admin login, v3 automatically writes the Dashboard, Entry, Reports, Admin, Setup, and Help website links into the spreadsheet's Settings tab.

The first email action may trigger a Google authorization request because v3 uses MailApp to send access codes.
4

Deploy the Apps Script web app

ondemand_video Need a quick walkthrough? Replay the 50-second setup tour.
  1. In Google Sheets (not your web browser's Extensions menu), choose Extensions → Apps Script
  2. Deploy → New deployment
  3. Type: Web app
  4. Execute as: Me
  5. Who has access: Anyone
  6. Deploy and copy the URL ending in /exec
5

Connect this browser

Paste the school's /exec deployment URL below. Production pages accept only API v3 or newer.

6

Build the job-site entry QR

Sign into Admin with the personal admin code and use Generate QR & Link. Entry staff receive only the restricted job-site link; they do not need Admin or Reports access.

system_update_alt

Do not make a new spreadsheet

Upgrade the existing school spreadsheet in place. Student records, entries, job sites, tasks, and existing report-viewer codes are preserved. V3 deliberately replaces the old security model.

1

Open the existing school's spreadsheet

Optional but sensible: use File → Make a copy as a backup before changing the script. Continue working in the original production spreadsheet.

2

Replace the bound Apps Script files

ondemand_video Not comfortable in Apps Script yet? Watch the 50-second setup tour.

In Google Sheets (not your web browser's Extensions menu), choose Extensions → Apps Script. Replace the entire contents of Code.gs. Then, in the Apps Script Files list, click the + beside Files → HTML, name it exactly Sidebar, and paste the complete Sidebar source. If Sidebar.html already exists, open it and replace all of its code.

Open v3 Code.gs Copy/Paste Document Open & Copy Sidebar Code
Code.gs opens the maintained Google Doc with copy/paste code. Sidebar opens a dedicated source-code page with a Copy button; it does not render the Sidebar UI. Save the Apps Script project after replacing both files. Do not create a new spreadsheet or new production deployment URL.
3

Return to the Sheet and refresh it

Opening/refreshing the spreadsheet runs the v3 migration. It creates missing security tabs, adds email columns to older access tables, preserves existing records, and marks the instance as schema v3.

Important: The first v3 migration automatically rotates the job-site entry token. Every pre-v3 QR code and saved entry link becomes invalid.
4

Create or confirm personal administrators

Open Vocational Tracker → Setup & Credentials. If the old tracker used one shared admin password, create the first named administrator with their email address.

Set a support email in the same sidebar if you want Admin-page feature requests emailed automatically. V3 will also keep the public Entry and other website links in the spreadsheet's Settings tab.

Once a personal administrator exists, v3 permanently removes the old password/password_hash settings. Old shared admin passwords are not accepted by v3 web pages.
5

Authorize credential email

Adding or regenerating a credential sends email through Apps Script. Google may ask the spreadsheet owner for permission to send email the first time. Complete that authorization.

Existing report viewers keep their current viewer code. Add their email address in the sidebar so the code can be emailed or re-sent.

6

Update the existing deployment

  1. Apps Script → Deploy → Manage deployments
  2. Open the existing Web app deployment with the pencil/Edit button
  3. Choose New version
  4. Keep Execute as: Me
  5. Keep Who has access: Anyone
  6. Deploy
Do not create a new deployment. Keeping the existing /exec URL preserves the school's browser configuration and avoids unnecessary relinking.
7

Verify that the existing URL is now v3

Paste the school's existing /exec URL. This checker will refuse any backend that does not report API v3 or newer.

8

Generate and replace every entry QR code

Sign into Admin with a personal admin code and generate the new entry QR. Replace all printed pre-v3 QR codes at job sites. Shared phones/tablets must scan the new code once.

9

Run the cutover test

  • Bare backend URL reports API v3 and reveals no student data.
  • Old entry QR fails.
  • New QR opens Entry and submits one test evaluation.
  • Report-only code opens Reports but cannot open Admin.
  • Admin code opens both Admin and Reports.
  • Disabling a viewer removes Reports access.
  • Disabling an admin removes Admin and Reports access.
  • The test entry appears correctly in Reports.
